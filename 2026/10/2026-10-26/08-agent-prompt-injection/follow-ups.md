## 用户原始回答（原文）

> 1. prompt注入攻击,agent可能忽视掉系统的提示词开始对主机进行操作
> 2. 不能,可能被prompt破壳
> 3. 我会不让这个agent去直接访问db,而是通过db工具来访问,同时在这个db工具中使用代码和当前使用者等context进行鉴权htpp工具也不能让他直接用,必须通过工具,最好在工具中采用白名单模式来使用

## 初步点评

1. **基本正确**：属于间接提示词注入（Indirect Prompt Injection）。恶意指令藏在上传 Word 文档这种不可信数据中，Agent 可能将数据错误提升为操作指令；风险具体取决于 SQL/HTTP 等工具权限，而非必然能控制主机。
2. **正确**：System Prompt 不构成强制访问控制边界。Jailbreak 与 Prompt Injection 有交集但并不完全相同，必须在模型外部的可信工具执行权限检查。
3. **回答较好**：DB 访问经受控工具；根据可信服务端认证上下文进行鉴权；HTTP 白名单。进一步应注意：
   - 不能让模型自行提供 `teacherId` 等身份并信任它；用户身份由服务端已验证会话注入。
   - 尽量提供 `getCourseScores(courseId)` 等业务工具，而不是任意 `querySql(sql)`；后端校验课程访问、使用参数化 SQL、最小权限账号、只读/限流/限时/限结果集。
   - HTTP 白名单需解析 URL 校验协议/主机名/端口/路径，防止前缀伪造、重定向、DNS/SSRF；更推荐最小权限的业务 HTTP 工具，而不是任意请求。
   - 若业务不需要通用 HTTP 工具，则不应开放。
