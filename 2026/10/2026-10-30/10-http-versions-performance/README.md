# 第 6 天第 10 题：HTTP/1.1、HTTP/2、HTTP/3 与前端性能

得分：49/100

## HTTP/1.1

HTTP/1.1 默认支持持久连接，同一个 TCP 连接可以先后处理多个请求，但不具备 HTTP/2 的并发多路复用。常见请求模式下，同一连接上的前一个请求/响应可能阻塞后续请求，称为队头阻塞。浏览器通常为同一来源建立多个连接来增加并发，代价是握手和资源开销。

## HTTP/2

HTTP/2 使用二进制 Frame 和 Stream，在一个 TCP 连接上交错传输多个请求与响应。每个帧标记 Stream 标识，接收方可重新组装。HTTP/2 缓解 HTTP 层队头阻塞，但仍使用 TCP 的有序字节流。若某个 TCP 数据段丢失，后续字节即使已收到，也可能无法交付上层，进而影响其他 HTTP/2 Stream。

## HTTP/3

HTTP/3 基于 QUIC；QUIC 构建在 UDP 之上，提供可靠传输、加密、多路复用及独立 Stream 的有序交付。一个 Stream 丢包，不必阻塞其他 Stream 的有序交付。但不同 Stream 仍共享拥塞控制和网络资源，丢包并非完全没有影响。

## 性能优化

HTTP/2 减少大量小请求的排队成本，因此无需像 HTTP/1.1 时代一样激进合并文件或使用雪碧图，但仍需权衡缓存、压缩和请求开销。不要将所有 JS 打成一个巨大 Bundle；可以采用路由级代码分割、动态 import、CDN、图片压缩及响应式图片、压缩与缓存、减少 JS 解析执行、关键资源优先加载。骨架屏主要改善感知，并不自动改善真实加载指标。使用 LCP、INP、CLS、Network Waterfall 和 Performance 进行针对性优化。

HTTP/1.1：8/25；HTTP/2：9/25；HTTP/3：12/25；工程优化：20/25。总分 49/100。
