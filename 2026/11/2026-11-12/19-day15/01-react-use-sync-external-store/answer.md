# 第 15 天 · 第 1 题：用户原始回答与评分

## 原题

React 如何安全地订阅外部状态？背景：WebSocket 持续更新外部 Store，多个 React 组件订阅。

1. 如果直接在 React 组件中使用 `useEffect + useState` 订阅这个 Store，会有什么潜在问题？
2. React 提供的 `useSyncExternalStore` 是用来解决什么问题的？它的三个参数分别承担什么职责？
3. 为什么 `getSnapshot()` 必须保证返回值具有稳定的引用？如果每次调用都返回一个新的对象，会发生什么？

### 用户原始回答（逐字）

> 1. 会有状态撕裂的问题吧
> 2. 解决在react中批量更新导致的状态撕裂,
> 3. 会导致组件异常更新

### 批改

- Q1：基本正确。状态撕裂是关键，还应指出渲染到 effect 订阅建立之间的更新遗漏。
- Q2：部分正确。不是批处理导致状态撕裂；三个参数 subscribe、getSnapshot、getServerSnapshot 未回答。
- Q3：正确方向。每次新对象会让快照比较持续变化，可能无限重新渲染；还需理解不可变更新。

## 第一次追问

1. 两个组件分别调用 `useSyncExternalStore` 订阅同一 Store，会建立两个独立订阅，还是自动合并？
2. 100 个组件订阅同一 Store，是否意味着 Store 更新时一定触发 100 次独立的 React 渲染？

### 用户原始回答（逐字）

> 1. 应该是合并成一个订阅吧,毕竟是共享数据
> 2. 不会吧

### 批改

- Q1：错误。共享数据不等于共享订阅；两个 Hook 调用通常分别建立订阅。
- Q2：需要区分：100 个订阅回调可能被触发，100 个组件也可能重新渲染，但 React 可以将多个更新批量提交。批处理不等于组件不渲染。

## 第二次追问

Store 初始为 `{ count: 0, username: "Alice" }`，更新为新对象 `{ count: 1, username: "Alice" }`：

1. 两个组件都通过 `useSyncExternalStore` 获取整个 state，是否都会重新渲染？
2. 使用 Selector 分别选择 count 和 username，哪个组件需要重新渲染？为什么？

### 用户原始回答（逐字）

> 1. 都会吧,引用地址变了
> 2. count变化的才会重新渲染吧

### 批改

- Q1：正确。整个 state 的引用变了，两个组件读取的快照都变了。
- Q2：正确。Selector 选出的 count 改变，username 未变，可跳过因这次 Store 更新导致的渲染。
