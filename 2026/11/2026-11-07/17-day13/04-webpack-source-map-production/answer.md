### 用户原始回答

**反馈：** 第 1 问基本正确，但 Source Map 通常是独立映射文件，不是简单把行列号附加进 JS。第 2 问初始不熟悉，讲解了 source-map、eval-source-map、cheap-module-source-map、hidden-source-map 的区别。第 3 问方向正确：生产环境不应公开暴露源码映射，但可以生成并私下上传给错误监控平台。

## 第一次追问：构建版本与 Source Map 匹配

**题目：** V1、V2 的 JS 不同，为什么不能使用 V2 Source Map 解析 V1 堆栈？不匹配会怎样？如何关联版本？

### 用户原始回答

> 1. 因为对不上
> 2. 会导致错误归因吧
> 3. 最好是毫秒时间戳+hash+版本号

**反馈：** 前两问正确。第三问可行，但不需要堆叠所有标识；Git Commit SHA、CI Build ID、Sentry Release 或 Debug ID 等可用于唯一关联构建产物和 Source Map。核心是精确匹配同一次构建。

## 第二次追问：hidden-source-map 与访问控制

**题目：** hidden-source-map 生成了 .map，但整个 dist 上传到公开 Nginx 目录，用户仍可访问。为什么？如何修改 CI/CD？

### 用户原始回答

> 1. 因为nginx没有拦截对map文件的访问呀
> 2. 把map文件抽离出来上传

**反馈：** 两问正确。hidden-source-map 仅隐藏 JS 中的 Source Map 引用注释，不删除文件也不限制 HTTP 访问。应将 .map 上传至 Sentry 等监控平台，然后从公开部署目录排除；Nginx 可以额外拒绝 .map 请求。
