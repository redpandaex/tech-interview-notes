## 主问题：异步搜索竞态

**题目：** React 搜索组件输入 react 后改为 vue，A（react）请求较慢、B（vue）请求较快，A 后返回覆盖 B；如何修复，清空输入框会怎样？

### 用户原始回答（包含对上一题幂等 Key 生命周期的追问）

> 这个幂等性key感觉有点问题,应该在什么时间又前端去获取呢?
>
> 应该不是每次点击创建订单id的按钮再去创建吧
>
> 1. 因为B请求比较长,属于异步里面比较常见的竞态竞争
> 2. 使用AbortControllr,在每次发送请求前先取消上一次的请求
> 3. 会出现,明明是空的,确显示错误的数据

**反馈：** 核心竞态理解正确，但原题中 A 比 B 更慢。AbortController 是有效方案；防抖不能完全消除响应乱序。清空输入框仍须让旧请求失效。对上一题补充说明：同一次创建操作第一次提交生成幂等 Key，超时重试复用，不能每次点击都重新生成；也可由服务端在结算流程开始时创建 checkout_id。

## 第一次追问：Request ID

**题目：** 无法取消请求时如何使用 requestIdRef 只允许最新响应更新 users？清空关键词时是否要递增？

### 用户原始回答

> 1. 每次发送请求时,使用nanoid生成一个新的id,用来对比上次的id
> 2. 需要,清空以后虚要讲展示数据复原的

**反馈：** 两问正确。nanoid 可行，但单组件内递增整数更简单。清空时必须递增版本，避免旧响应覆盖清空后的状态。

## 第二次追问：loading 状态竞态

**题目：** A、B 并发，A 先完成在 finally 中设置 loading=false，B 尚未结束，会出现什么 UI 问题？如何修改？

### 用户原始回答

> 1. 会造成显示错误的数据
> 2. 应该改成finally里面判断还有没有有效的请求id,没有的话才结束

**反馈：** 第 1 问不准确：题目针对 loading 提前结束，可能导致加载动画提前消失、按钮提前可点击等，不必然是数据错误。第 2 问方向正确，应精确判断 `requestId === requestIdRef.current`，只有最新请求才允许在 finally 中关闭 loading。
